
# API Contract

## 1. Overview

Backend: FastAPI
Frontend: Next.js / TypeScript

API version: v1

Base path:

    /api/v1

Data format:

    application/json

The API manages experiments and provides telemetry.

Pose estimation computations belong in the Python
simulation, model, and estimator modules.

## 2. API Endpoints

### GET /api/v1/health

Returns the service health.

Response:

{
  "status": "healthy",
  "api_version": "v1",
  "models_loaded": false
}

### GET /api/v1/scenarios

Returns available trajectory configurations.

Response:

{
  "scenarios": [
    {
      "id": "Approach_L1",
      "name": "Nominal Approach",
      "duration_seconds": 10.0,
      "simulation_fps": 100,
      "description": "Synthetic formation approach"
    }
  ]
}

### GET /api/v1/estimators

Returns supported estimation methods.

Response:

{
  "estimators": [
    {
      "id": "ann",
      "name": "ANN Coarse Classification",
      "output_type": "coarse_pose"
    },
    {
      "id": "paper_pf",
      "name": "Original Particle Filter",
      "output_type": "pose_6dof"
    },
    {
      "id": "improved_pf",
      "name": "Improved Particle Filter",
      "output_type": "pose_6dof"
    },
    {
      "id": "pnp",
      "name": "PnP Pose Estimator",
      "output_type": "pose_6dof"
    },
    {
      "id": "geometric",
      "name": "Geometric Refinement",
      "output_type": "pose_6dof"
    }
  ]
}

### POST /api/v1/experiments

Creates a new experiment.

Request example:

{
  "scenario_id": "Approach_L1",
  "estimators": [
    "ann",
    "paper_pf",
    "improved_pf",
    "pnp"
  ],
  "parameters": {
    "particle_count": 5000,
    "resampling_alpha": 0.9,
    "pixel_noise_std": 1.5,
    "seed": 42
  }
}

Response:

{
  "experiment_id": "exp_example_001",
  "status": "pending"
}

The experiment_id above is an illustrative identifier.

Actual identifiers must be generated by the backend.

### GET /api/v1/experiments/{id}

Returns experiment status.

Response:

{
  "experiment_id": "exp_example_001",
  "status": "completed",
  "progress": 1.0,
  "error": null
}

Supported status values:

- pending
- running
- completed
- failed

### GET /api/v1/experiments/{id}/telemetry

Returns synchronized frame records.

Response structure:

{
  "experiment_id": "exp_example_001",
  "scenario_id": "Approach_L1",
  "simulation_fps": 100,
  "playback_fps": 50,
  "frame_count": 500,
  "frames": []
}

The frames array is populated with actual experiment
outputs, not static example values.

### GET /api/v1/experiments/{id}/summary

Returns computed evaluation metrics.

Response structure:

{
  "experiment_id": "exp_example_001",
  "metrics": {},
  "runtime": {},
  "metadata": {}
}

## 3. Standard Frame Schema

Each telemetry frame contains:

{
  "frame_index": 0,
  "timestamp": 0.0,

  "observation": {
    "keypoints": [],
    "visible": []
  },

  "ground_truth": {
    "position": [],
    "quaternion": []
  },

  "ann": {
    "class_id": 0,
    "confidence": null,
    "coarse_position": [],
    "coarse_roll_rad": null
  },

  "estimates": {},

  "errors": {},

  "diagnostics": {}
}

Field contracts:

observation.keypoints:
    Exactly 14 entries.

    Each entry is either:
    [u, v] for a visible feature, or
    null for an invisible feature.

observation.visible:
    Exactly 14 booleans.

ground_truth.position:
    Exactly three coordinates in meters.

ground_truth.quaternion:
    Exactly four values in [qx, qy, qz, qw] order.

ann.class_id:
    Integer between 0 and 4799.

ann.confidence:
    The probability assigned to the selected class
    when calibrated probabilities are available.

ann.coarse_position:
    Three coordinates in meters.

ann.coarse_roll_rad:
    One angle in radians.

estimates:
    Dictionary keyed by continuous estimator ID.

errors:
    Evaluation metrics keyed by estimator ID.

diagnostics:
    Runtime and estimator-specific diagnostics.

## 4. Continuous Estimator Schema

Each entry in estimates must follow:

{
  "position": [0.0, 0.0, 0.0],
  "quaternion": [0.0, 0.0, 0.0, 1.0],
  "frame_from": "L",
  "frame_to": "F",
  "runtime_ms": 0.0,
  "covariance": null
}

These numbers are schema examples, not experimental data.

Position uses meters.

Quaternions use [qx, qy, qz, qw].

Angles are expressed in radians when transported by API.

Dashboard conversions to degrees are presentation-only.

The covariance field may be null when unavailable.

## 5. Missing Values

JSON must not contain NaN or Infinity.

Invalid or missing numerical values are serialized as null.

Occluded landmarks are represented by:

    keypoints[i] = null
    visible[i] = false

Unavailable estimates must not be replaced by
identity poses or zero error values.

## 6. Experiment Execution

The API creates a new experiment for every distinct
parameter configuration.

Experiments are immutable once completed.

A new parameter configuration produces a new
experiment identifier.

The frontend does not perform estimator mathematics.

## 7. Playback Synchronization

Every frame contains a simulation timestamp.

All visual components use the same active frame index.

The frontend synchronizes:

- Camera tracker
- 3D trajectories
- Particle samples
- Position error graph
- Attitude error graph
- Numerical diagnostics

Playback speed affects presentation only.

It does not alter numerical estimation results.

## 8. Performance Telemetry

Backend estimator runtime is recorded independently
from frontend rendering performance.

Fields may include:

    estimator_runtime_ms
    effective_sample_size
    particle_count
    resampling_performed
    particle_spread

Rendering large particle populations may use sampled
points while preserving accurate backend statistics.

## 9. Serialization Rules

All API values must be JSON serializable.

NumPy arrays must be converted to lists.

NumPy scalars must be converted to standard Python types.

Non-finite floats must become null.

All vector shapes must be validated before serialization.

## 10. Errors

Validation errors:
    HTTP 422

Unknown experiment:
    HTTP 404

Invalid experiment operation:
    HTTP 409

Unexpected server failure:
    HTTP 500

Experiment execution failures should be stored as
failed experiment states with sanitized error messages.

## 11. Versioning

All current routes use /api/v1.

Breaking changes to the telemetry contract require
an API version change.

Additional optional diagnostic fields may be introduced
without breaking existing consumers.
